BAB 01

Algoritma dan program pertama

Ubah masalah menjadi langkah terurut yang dapat dijalankan.

TUJUAN BELAJAR

Setelah bab ini, kamu dapat mengidentifikasi input, proses, output, menyusun kontrak sederhana, dan menjalankan program Python interaktif.

◎
01

Berpikir dengan input, proses, output

Algoritma adalah urutan langkah yang jelas untuk menyelesaikan masalah.

Bayangkan petugas pendaftaran seminar. Nama peserta adalah input, menyusun sapaan adalah proses, dan pesan konfirmasi adalah output. Langkahnya harus jelas agar masukan yang sama memberi hasil yang dapat diperkirakan.

↓INPUTNama peserta"Rani"
→
⚙PROSESSusun sapaanf"Halo, {nama}"
→
↑OUTPUTPesan konfirmasiHalo, Rani!
✦

Algoritma ≠ program. Algoritma adalah rancangan langkahnya; program adalah algoritma yang ditulis dalam bahasa yang bisa dieksekusi komputer.

Mulai dari kontrak

Sebelum menulis kode, tetapkan data yang tersedia, hasil yang diminta, dan syarat keberhasilan. Contoh kontrak kartu peserta:

  • Nama dan NIM wajib diisi setelah spasi tepi dibuang.
  • NIM disimpan sebagai teks agar nol depan tetap ada.
  • Kartu diterbitkan hanya jika seluruh data wajib lengkap.
Telusuri contoh input
TahapKeadaan
Inputnama = " Siti Aminah ", NIM = "00125"
Normalisasinama = "Siti Aminah", NIM tetap "00125"
ValidasiKedua teks tidak kosong → lolos
OutputKartu peserta lengkap ditampilkan

Coba pikirkan: apakah nama yang isinya tiga spasi sudah memenuhi kontrak? Apa yang harus dilakukan sebelum memutuskan?

02

Validasi sebelum menampilkan kartu

Laporkan semua data yang kurang, jangan tampilkan keberhasilan palsu.

Data yang hanya berisi spasi dianggap kosong setelah .strip(). Kumpulkan semua kesalahan terlebih dahulu; jangan berhenti pada kesalahan pertama. Nama dan kota dua kata tetap utuh, sedangkan NIM bukan angka hitung.

Python · kartu peserta
nama = input("Nama lengkap: ").strip()
nim = input("NIM: ").strip()
kelas = input("Kelas: ").strip().upper()
kota = input("Kota: ").strip()

data = {"Nama": nama, "NIM": nim,
        "Kelas": kelas, "Kota": kota}
kosong = [label for label, nilai in data.items()
          if not nilai]

if kosong:
    print("Belum lengkap:", ", ".join(kosong))
else:
    for label, nilai in data.items():
        print(f"{label}: {nilai}")
!

Kenapa NIM bertipe teks? Mengubah `"00125"` menjadi integer menghasilkan `125`. Nol depan adalah bagian identitas, bukan nilai untuk dijumlahkan.

Kasus batas: jika nama, NIM, dan kota kosong sedangkan kelas terisi, program menyebut ketiga kolom yang kurang sekaligus dan tidak mencetak kartu.

03

Menghitung biaya kegiatan

Pisahkan nilai tetap, tarif per orang, dan jumlah peserta.

Biaya tetap Rp50.000 dan konsumsi Rp12.000 per peserta. Untuk lima peserta, hitung konsumsi dahulu, lalu tambahkan biaya tetap.

konsumsi5 × Rp12.000 = Rp60.000totalRp50.000 + Rp60.000 = Rp110.000
Python · biaya kegiatan
BIAYA_TETAP = 50_000
KONSUMSI_PER_ORANG = 12_000
peserta = int(input("Banyak peserta: "))

if peserta <= 0:
    print("Peserta harus lebih dari nol.")
else:
    konsumsi = peserta * KONSUMSI_PER_ORANG
    total = BIAYA_TETAP + konsumsi
    print(f"Total rencana: Rp{total}")

Input 1 menghasilkan Rp62.000. Input 0 atau bilangan negatif ditolak. Input teks seperti abc tidak dapat dikonversi dengan int(); versi yang lebih tangguh menangani kesalahan format tersebut dan menjelaskan penolakannya.

Kerjakan tugas dengan spesifikasi, dry run, program, dan bukti pengujian.

  1. Dasar: tambahkan kota asal ke perkenalan lengkap.

  5. Adaptasi kartu: wajibkan nama, NIM, dan kelas; pertahankan NIM teks dan anggap spasi saja sebagai kosong. Bandingkan kontrak lama dan baru dengan satu input.

  2. Kolom kosong: nama kosong menghasilkan pesan Nama belum diisi.; tidak ada kartu sukses. Semua kolom kosong dilaporkan bersamaan.
  3. Tiga peserta: satu perulangan for menjalankan baca–validasi–tampil tepat tiga kali. Peserta yang ditolak tidak menghentikan peserta berikutnya.
  4. Sapaan: pagi menghasilkan “Selamat pagi” dan sore menghasilkan “Selamat sore”; NIM dan kolom identitas tidak berubah.
  5. Kartu wajib: versi tiga kolom dibandingkan dengan versi nama/NIM/kelas/kota. 00125 tetap teks; input spasi saja ditolak; kartu hanya keluar bila lengkap.

Implementasi ada di folder Bab 1; tes otomatis mencakup kartu normal, banyak kolom kosong, sapaan salah, pendaftaran berulang, batas biaya, dan input invalid.

Studi kasus mandiri dan kunci analisis

Kasus: buat kartu kegiatan berisi nama, NIM, kelas, dan kota. Semua wajib terisi; tampilkan seluruh kolom yang kurang sekaligus; NIM tidak boleh kehilangan nol depan. Tambahkan pilihan sapaan pagi/sore.

  1. Tujuan/pengguna: membantu panitia menerbitkan kartu peserta; output-nya kartu atau daftar kesalahan.
  2. Urutan: baca teks → trim → cek seluruh kolom dan sapaan → tampilkan semua kekurangan, atau terbitkan kartu.
  3. Data: nama/NIM/kelas/kota/waktu bertipe teks; NIM tetap teks; normalisasi mendahului validasi.
  4. Trace: `" Siti Aminah "`, `"00125"`, `"a"`, `"Bandung"`, `"pagi"` menjadi nama `Siti Aminah`, NIM `00125`, kelas `A`, kota `Bandung`; semua lolos.
  5. Batas: tiga spasi menjadi kosong; beberapa kolom kosong harus dilaporkan bersamaan. Batas maksimum teks tidak ditentukan.
  6. Regresi: nama dua kata dan NIM `00125` tetap; versi pengembangan menambah kota dan sapaan sebagai input.

Evaluasi: algoritma adalah rancangan langkah, program implementasinya; strip() membuang spasi tepi; profil dicetak setelah input lengkap. Uji biaya satu peserta menghasilkan Rp62.000. Input abc ditolak saat konversi tanpa menghitung total. Kartu dan biaya sama-sama memakai IPO tetapi memvalidasi aturan berbeda. Uji NIM nol depan dan multi-kekurangan mengungkap bug konversi NIM atau pemeriksaan kolom yang tidak lengkap.

Jawaban evaluasi formatif dan refleksi (1–9)
  1. Algoritma adalah urutan langkah untuk menyelesaikan masalah; program adalah implementasi langkah tersebut dalam bahasa pemrograman.
  2. NIM bertipe teks karena identitas bukan besaran hitung dan nol di depan harus dipertahankan.
  3. strip() menghapus spasi di awal/akhir teks, bukan spasi tengah.
  4. Kartu dicetak setelah semua kolom wajib dan pilihan sapaan lolos pemeriksaan.
  5. Batas biaya 1 peserta menghasilkan Rp62.000: 50.000 + 1 × 12.000. Kondisi peserta harus positif menentukan jalur hitung.
  6. abc gagal dikonversi ke integer; program menampilkan pesan dan tidak menghitung total. Uji memeriksa tidak ada output sukses.
  7. Profil dan biaya sama-sama mengikuti input–proses–output. Profil memvalidasi teks wajib, sedangkan biaya memvalidasi bilangan dan melakukan aritmetika.
  8. Kesalahan rawan: mengubah NIM menjadi angka atau hanya memeriksa kolom pertama. Uji 00125 dan beberapa kolom kosong akan menemukan kesalahan itu.
  9. Dipahami: pilihan tipe data memengaruhi makna hasil. Perlu dipelajari: perulangan/penyimpanan kumpulan data; contoh nyatanya pendaftaran tiga peserta.

Hubungannya: kontrak IPO Bab 1 menjadi dasar flowchart dan pseudocode Bab 2. Batas contoh: biaya hanya memakai jumlah peserta bulat positif dan belum menyimpan data secara permanen.

02

Luas dan keliling persegi panjang

Validasi kedua sisi sebelum menghitung dan menampilkan hasil.

INPUTPanjang p dan lebar lAngka positif, satuan sama
PROSESL = p × lK = 2 × (p + l)
OUTPUTLuas dan kelilingSatuan² dan satuan panjang
PseudocodeALGORITMA
MULAI
BACA panjang, lebar
JIKA panjang <= 0 ATAU lebar <= 0
    TULIS "Sisi harus positif."

    luas <- panjang * lebar
    keliling <- 2 * (panjang + lebar)
    TULIS luas dan keliling

Python · luas & keliling
panjang = float(input("Panjang (m): "))
lebar = float(input("Lebar (m): "))

if panjang <= 0 or lebar <= 0:
    print("Sisi harus positif.")
else:
    luas = panjang * lebar
    keliling = 2 * (panjang + lebar)
    print(f"Luas = {luas:.2f} m2")
    print(f"Keliling = {keliling:.2f} m")
Dry run: panjang 5 m, lebar 3 m
LangkahNilai

Luas5 × 3 = 15 m²
Keliling2 × (5 + 3) = 16 m
OutputLuas 15.00 m2 · Keliling 16.00 m

Sisi nol dan negatif ditolak. Samakan satuan sebelum menghitung: 5 m × 30 cm harus dinormalisasi menjadi 5 m × 0,30 m = 1,50 m².

03

Tarif parkir dengan batas harian

Perhatikan jam pertama, jam tambahan, lalu kebijakan batas tarif.

Tarif latihan Rp3.000 untuk satu jam pertama, lalu Rp2.000 per jam tambahan. Durasi harus bilangan bulat minimal satu jam. Pengembangan menerapkan batas maksimal harian Rp15.000 setelah tarif awal dihitung.

tarif awal3.000 + (jam − 1) × 2.000tarif akhirmin(tarif awal, 15.000)
Python · hitung tarif
jam = int(input("Durasi parkir (jam): "))

if jam < 1:
    print("Durasi minimal satu jam.")
else:
    jam_tambahan = jam - 1
    biaya_awal = 3000 + jam_tambahan * 2000
    biaya_akhir = min(biaya_awal, 15000)
    print(f"Biaya awal: Rp{biaya_awal}")
    print(f"Tarif akhir: Rp{biaya_akhir}")
1 jam → Rp3.0003 jam → Rp7.0007 jam → Rp15.0008 jam → tetap Rp15.000

Kesalahan umum: rumus jam * 2000 untuk biaya tambahan menghitung jam pertama dua kali. Uji satu jam akan membongkar bug tersebut.

Simpan nilai lama sebelum menimpa variabel.

a = input("Isi wadah A: ")
b = input("Isi wadah B: ")

sementara = a
a = b
b = sementara

print(f"Sesudah: A={a}, B={b}")

Jika langsung menulis a = b, isi awal a hilang. Saat b = a dilakukan sesudahnya, kedua variabel akan berisi nilai yang sama. Variabel sementara menjaga nilai yang masih diperlukan.

Praktikum, tantangan, dan tugas Bab 2

Samakan narasi, pseudocode, diagram, kode, dan hasil dry run.

Praktikum terbimbing: rancangan tarif parkir

  1. Tulis narasi yang menyebut satuan durasi.
  2. Gambar flowchart lengkap dengan keputusan dan cabang berlabel.
  3. Dry run 5 jam, 3 jam, dan 0 jam sebelum menulis kode.
  4. Bandingkan setiap cabang kode dengan flowchart dan perbaiki yang tidak cocok.
  5. Tetapkan kontrak input valid, output, dan penolakan; pisahkan aturan wajib dan fitur pengembangan.
  6. Dry run satu kasus normal dan satu batas.
  7. Implementasikan bertahap sambil menjaga hasil lama (regresi).
  8. Uji penolakan dan simpan input pemicu serta hasil sebelum/sesudah perbaikan bug.

Tantangan bertingkat

  1. Dasar: tulis pseudocode keliling persegi panjang.
  2. Menengah: tampilkan luas dan keliling dari satu kali pembacaan input.
  3. Lanjut: konversikan sentimeter ke meter sebelum menghitung luas.
  4. Pengembangan: tambahkan batas tarif harian Rp15.000 sesudah biaya awal dihitung dan perbarui ketiga representasi.
  5. Adaptasi parkir: jam bulat minimal 1; Rp3.000 jam pertama, Rp2.000 per jam tambahan. Tulis pseudocode dan flowchart, pastikan jam pertama tidak dihitung dua kali, lalu bandingkan perubahan aturan dengan input yang sama.
  6. Pembuktian pertukaran: tukar nilai teks dengan variabel bantu; trace nilai awal, nilai sementara, dan hasil; tambahkan penolakan input nonteks pada helper.
Pembahasan dan hasil uji semua tantangan 1–6
  1. Keliling: keliling = 2 × (panjang + lebar); 5 m dan 3 m menghasilkan 16 m.
  2. Luas dan keliling: kedua sisi dibaca sekali; 5 × 3 menghasilkan luas 15 m² dan keliling 16 m.
  3. Konversi satuan: 250 cm dibagi 100 menjadi 2,5 m sebelum hitung; dengan lebar 4 m, luas 10 m² dan keliling 13 m.
  4. Batas tarif: 7 jam = Rp15.000; 8 jam biaya awal Rp17.000 dibatasi menjadi Rp15.000; 3 jam tetap Rp7.000.
  5. Tarif bertingkat: tambahan = jam − 1. Satu jam menghasilkan Rp3.000, bukan Rp5.000; tiga jam menghasilkan Rp7.000.
  6. Pertukaran: merah/biru → simpan merah → A menjadi biru → B menjadi merah. Uji tipe salah ditolak tanpa hasil sukses.

Narasi, pseudocode, flowchart, dan kode untuk parkir menerapkan keputusan yang sama. Tes otomatis juga mencakup sisi nol/negatif, input bukan angka, overflow/underflow, serta pertukaran teks.

Studi kasus mandiri dan kunci analisis

Kasus: durasi parkir jam bulat minimal satu. Tarif Rp3.000 untuk jam pertama dan Rp2.000 per jam tambahan. Pengembangan menerapkan tarif maksimum Rp15.000.

  1. Tujuan/input/output: hitung tarif dari durasi; tampilkan biaya awal dan tarif akhir; jam harus bilangan bulat positif.
  2. Alur: baca jam → bila jam < 1, tolak dan selesai → hitung tambahan dan biaya awal → batasi dengan min(biaya_awal, 15000) → tampilkan.
  3. Data: jam, jam tambahan, dan biaya rupiah adalah integer. Hasil hanya dibuat pada cabang valid.
  4. Trace: 3 jam → tambahan 2 → biaya awal Rp7.000 → biaya akhir Rp7.000.
  5. Batas: 1 jam Rp3.000; 7 jam tepat Rp15.000; 0 dan negatif ditolak. Input teks bukan jam bulat.
  6. Regresi: 3 jam tetap Rp7.000; 8 jam berubah dari Rp17.000 menjadi Rp15.000 karena aturan batas.

Evaluasi: pseudocode menjelaskan algoritma bebas bahasa; dua jalur keputusan membedakan valid/tidak; variabel sementara menjaga nilai yang akan ditimpa. Uji satu jam menemukan rumus biaya tambahan yang keliru karena hasil wajib Rp3.000, bukan Rp5.000.

Jawaban evaluasi formatif dan refleksi (1–9)
  1. Pseudocode menyatakan langkah serta keputusan secara terstruktur tanpa bergantung pada sintaks bahasa tertentu.
  2. Keputusan memiliki jalur Ya/Tidak agar keadaan valid dan tidak valid menghasilkan alur yang berbeda.
  3. Variabel sementara menyimpan nilai lama sebelum nilai lain ditimpa saat pertukaran.
  4. Masukkan contoh yang sama ke narasi, pseudocode, flowchart, dan kode; bandingkan syarat, rumus, cabang, dan output.
  5. Uji batas sisi 0 dan 3 harus ditolak karena kedua sisi wajib positif; tidak boleh menampilkan hasil luas.
  6. Input abc gagal saat parsing sehingga luas tidak dihitung. Input sangat besar dapat menyebabkan overflow; hasil tak hingga juga ditolak.
  7. Luas dan parkir sama-sama memeriksa prasyarat dahulu. Luas mengalikan dua sisi positif; parkir menerapkan tarif dasar lalu tambahan jam.
  8. Bug rawan: menghitung tarif tambahan sebanyak jam, bukan jam - 1. Uji 1 jam harus Rp3.000 dan mengungkap kekeliruan.
  9. Dipahami: setiap cabang diagram harus sejalan dengan kode. Perlu dipelajari: normalisasi satuan; 250 cm harus menjadi 2,5 m sebelum hitung.

Hubungannya: Bab 2 mengubah spesifikasi IPO Bab 1 menjadi representasi algoritma yang dapat ditelusuri. Batas contoh: tarif adalah model latihan, hanya memakai jam bulat, dan batas Rp15.000 diterapkan pada satu transaksi.

BAB 03

Variabel, tipe data, dan konversi

TUJUAN BELAJAR

Gunakan variabel, tipe data, input, output, konversi tipe dan satuan dengan tepat; telusuri bagaimana nilai berubah.

ƒ
01

Variabel menyimpan makna, bukan hanya nilai

Nama yang jelas membantu memilih operasi yang benar.

Variabel adalah nama yang merujuk ke suatu objek. suhu = 30 membuat nama suhu merujuk angka 30; penugasan berikutnya dapat mengubah nilai yang dirujuknya. Python peka huruf besar-kecil. Gunakan nama yang menyebut satuan seperti jarak_km.

42intBilangan bulatjumlah = 12
3.5floatBilangan pecahanvolume_l = 2.5
AastrTeks / identitasnim = "00125"
✓boolBenar atau salahaktif = True
!

Input selalu bertipe str. Teks "2" + "3" menghasilkan "23". Konversi keduanya menjadi integer untuk memperoleh 5. Jangan gunakan bool("tidak"): string apa pun yang tidak kosong bernilai True.

Konversi tipe dengan sengaja

Input → konversi → hitung
teks = input("Masukkan jumlah: ")
jumlah = int(teks)
total = jumlah + 3
print(total)  # Masukan 12 menghasilkan 15

Gunakan int untuk jumlah benda, float untuk ukuran yang mungkin pecahan, str untuk nama/NIM/kode pos, dan bool untuk status yang sudah ditafsirkan dengan aturan eksplisit.

02

Konversi Celsius, Fahrenheit, dan Kelvin

Jaga rumus, tipe, dan batas fisik suhu.

FAHRENHEITF = C × 9 / 5 + 32KELVINK = C + 273.15
Python · konversi suhu
celsius = float(input("Suhu Celsius: "))
if celsius < -273.15:
    print("Suhu di bawah nol mutlak.")
else:
    fahrenheit = celsius * 9 / 5 + 32
    kelvin = celsius + 273.15
    print(f"Fahrenheit: {fahrenheit:.2f}")
    print(f"Kelvin: {kelvin:.2f}")
0°C → 32°F · 273.15 K100°C → 212°F · 373.15 K−40°C → −40°F · 233.15 K−273.15°C → 0 K

Program menolak suhu di bawah nol mutlak (−273.15°C), batas yang ditambahkan pada latihan. Format .2f hanya mengatur tampilan dua desimal; nilai numerik untuk perhitungan tidak berubah.

03

Pecah durasi dan jarak dengan // serta %

Pembagian bulat menghitung unit penuh; modulo mengambil sisa.

/Pembagian biasa135 / 60 = 2.25
//Pembagian bulat135 // 60 = 2 jam
%Sisa pembagian135 % 60 = 15 menit
Python · menit menjadi jam dan sisa
menit = int(input("Durasi (menit): "))
if menit < 0:
    print("Durasi tidak boleh negatif.")
else:
    jam = menit // 60
    sisa_menit = menit % 60
    total_detik = menit * 60
    print(f"{jam} jam {sisa_menit} menit")
    print("Total detik:", total_detik)
    print("Periksa:", jam * 60 + sisa_menit)
↺

Invariant / pemeriksaan balik: jam × 60 + sisa_menit harus sama dengan menit awal. Untuk 135, 2 × 60 + 15 = 135. Nilai sisa selalu antara 0 dan 59.

Konversi jarak mengikuti pola sama: untuk 2.345 meter, 2345 // 1000 = 2 km dan 2345 % 1000 = 345 m.

04

Kecepatan rata-rata: satuan harus cocok

Ubah waktu ke jam sebelum membagi kilometer.

KONVERSI WAKTUwaktu_jam = waktu_menit / 60KECEPATANkm/jam = jarak_km / waktu_jam
Python · hitung kecepatan
jarak_km = float(input("Jarak (km): "))
waktu_menit = float(input("Waktu (menit): "))

if jarak_km < 0 or waktu_menit <= 0:
    print("Jarak harus >= 0 dan waktu > 0.")
else:
    waktu_jam = waktu_menit / 60
    kecepatan = jarak_km / waktu_jam
    print(f"Kecepatan: {kecepatan:.2f} km/jam")

Dry run: 15 km dalam 30 menit → waktu 30/60 = 0,5 jam → kecepatan 15/0,5 = 30 km/jam. Jarak nol sah jika waktunya positif; waktu nol ditolak sebelum pembagian.

!

Membagi kilometer langsung dengan menit menghasilkan km/menit, bukan km/jam. Angka bisa tampak masuk akal, tetapi label satuannya keliru.

Praktikum, tantangan, dan tugas Bab 3

Latih konversi tipe dan satuan dengan dry run serta pemeriksaan balik.

Praktikum terbimbing: konverter kegiatan

  1. Buat tabel Celsius, Fahrenheit, dan Kelvin untuk semua data uji.
  2. Uji mengganti float(input()) dengan input(); jelaskan mengapa operasi matematis gagal pada string.
  3. Buat berkas terpisah untuk mengubah kilometer menjadi meter; contoh 1,25 km menjadi 1.250 m. Program studi kasus sebaliknya mengubah meter menjadi kilometer dan sisa meter.
  4. Bedakan kesalahan format (teks bukan angka) dan kesalahan rumus atau satuan.
  5. Tetapkan kontrak input valid, output, pesan penolakan, serta fitur pengembangan.
  6. Lakukan dry run normal dan batas sebelum mengetik.
  7. Implementasikan versi terkecil lalu tambah fitur bertahap dengan menjaga regresi.
  8. Uji penolakan dan catat input pemicu serta hasil sebelum/sesudah perbaikan bug.

Tantangan bertingkat

  1. Dasar: konversikan menit bulat menjadi detik.
  2. Menengah: pecah 135 menit menjadi 2 jam 15 menit dengan // dan %.
  3. Lanjut: tolak suhu Celsius di bawah −273,15; uji nilai tepat di batas dan sedikit di bawahnya.
  4. Pengembangan: konversikan meter menjadi kilometer dan meter sisa; pisahkan nama peserta dari variabel pengukuran.
  5. Adaptasi durasi: input menit bulat tidak negatif dan tampilkan jam/sisa; bandingkan versi awal dengan versi pengembangan yang juga menampilkan detik dan pemeriksaan balik.
  6. Pembuktian kecepatan: ubah menit ke jam sebelum menghitung km/jam; gunakan jarak nol sebagai uji batas sah dan waktu nol sebagai uji penolakan.
Pembahasan dan hasil uji semua tantangan 1–6
  1. Menit ke detik: detik = menit × 60; 135 menit menjadi 8.100 detik; 0 diterima, nilai negatif ditolak.
  2. Jam dan sisa: 135 // 60 = 2 dan 135 % 60 = 15; hasilnya 2 jam 15 menit. Tidak menggunakan pembulatan pembagian biasa.
  3. Nol mutlak: −273,15°C diterima sebagai batas dan menghasilkan 0 K; −273,16°C ditolak.
  4. Jarak: 2.345 m menjadi 2 km 345 m dengan // 1000 dan % 1000; identitas nama tetap terpisah. Program tambahan mengubah 1,25 km menjadi 1.250 m.
  5. Durasi: pengembangan menambah total detik dan pemeriksaan balik tanpa mengubah 135 menit → 2 jam 15 menit. Invariant: jam * 60 + sisa == menit.
  6. Kecepatan: 0 km dalam 20 menit sah dan menghasilkan 0 km/jam. 10 km dalam 0 menit ditolak sebelum pembagian.

Implementasi dan tes ada di folder Bab 3; tes meliputi format, nilai batas, penolakan, konversi dua arah satuan jarak, dan invariant rekonstruksi.

Studi kasus mandiri dan kunci analisis

Kasus: konverter membaca menit bulat tidak negatif, menghasilkan jam, sisa menit, detik total, dan rekonstruksi. Pengembangan menambah jarak meter ke kilometer dan sisa meter.

  1. Tujuan: membantu peserta/panitia membaca durasi dan jarak kegiatan dalam unit yang sesuai.
  2. Urutan: parse dan validasi → jam = menit // 60 → sisa = menit % 60 → detik → rekonstruksi → kilometer dan sisa meter → tampilkan.
  3. Data: nama berupa teks; menit dan meter berupa integer. Identitas tidak dicampur ke besaran yang dihitung.
  4. Trace: `Rani`, 135 menit, 2345 m → 2 jam 15 menit, 8100 detik, balik 135, 2 km 345 m.
  5. Batas: nol diterima; 59/60/61 menghasilkan 0:59, 1:00, 1:01. Nilai negatif ditolak. Nilai maksimum tidak ditentukan soal; integer Python dibatasi memori.
  6. Regresi: durasi 135 menit tetap menjadi 2 jam 15 menit; versi baru menambah detik, pemeriksaan balik, dan jarak.

Evaluasi: input bertipe str; / adalah pembagian biasa, // pembagian bulat. Periksa durasi dengan jam * 60 + sisa == menit. Format .2f tidak mengubah nilai hitung. Bandingkan konverter Celsius dan durasi: sama-sama mengonversi input sebelum hitung, tetapi tipe dan operasi berbeda. Uji batas 59/60/61 menangkap kesalahan penggunaan pembagian biasa untuk durasi.

Jawaban evaluasi formatif dan refleksi (1–9)
  1. input() selalu menghasilkan str, termasuk ketika pengguna mengetik angka.
  2. / menghasilkan pembagian biasa (dapat berupa pecahan); // mengambil hasil bulat ke bawah.
  3. Periksa dengan jam * 60 + sisa == menit, 0 <= sisa < 60, dan detik == menit * 60.
  4. .2f mengatur tampilan dua desimal, bukan mengubah nilai numerik yang dihitung.
  5. Pada −273,15°C, Kelvin tepat 0 dan input diterima. Kondisi di bawah konstanta nol mutlak menentukan penolakan.
  6. Durasi negatif ditolak sebelum hasil dibuat; bukti uji adalah pesan penolakan dan tidak ada output konversi.
  7. Suhu dan durasi sama-sama parse input sebelum menghitung. Suhu memakai float dan rumus skala; durasi memakai int, //, dan %.
  8. Kesalahan rawan adalah menggunakan / atau round() untuk durasi. Kasus 59, 60, dan 61 menit menguji batas unit secara langsung.
  9. Dipahami: hasil pembagian bulat dan modulo dapat diperiksa dengan rekonstruksi. Perlu dipelajari: presisi floating-point pada suhu/kecepatan.

Hubungannya: tipe dan konversi Bab 3 memakai urutan dan keputusan dari Bab 2 serta kontrak IPO Bab 1. Batas contoh: durasi/jarak berupa integer; program tidak menyimpan data peserta secara permanen.
