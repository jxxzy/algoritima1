01

Kontrak fungsi: parameter dan argumen

Definisi menyatakan syarat dan hasil; pemanggilan memberikan data.

Parameter adalah nama pada definisi def hitung_bayar(subtotal). Argumen adalah nilai saat pemanggilan, misalnya hitung_bayar(100000). Variabel lokal hanya ada selama pemanggilan. Hindari variabel global yang diam-diam mengubah hasil.

DEFINISIdef hitung_diskon(subtotal):PARAMETERsubtotalARGUMENhitung_diskon(100000)

Kontrak menyebut makna parameter, prasyarat, satuan, dan hasil. Fungsi hitung diskon menerima subtotal rupiah tidak negatif dan mengembalikan diskon rupiah. Validasi pada main tidak secara otomatis membuat fungsi aman bagi semua pemanggil; kontrak perlu dipatuhi atau fungsi perlu menegakkannya.

Python · fungsi diskon
def hitung_diskon(subtotal):
    if subtotal < 0:
        raise ValueError("Subtotal tidak boleh negatif")
    if subtotal >= 100000:
        return subtotal * 10 // 100
    return 0

def hitung_bayar(subtotal):
    return subtotal - hitung_diskon(subtotal)
02

return, fungsi murni, dan refactoring aman

Pisahkan komputasi dari input dan output untuk pengujian yang terarah.

return mengirim nilai ke pemanggil dan mengakhiri jalur fungsi itu. print hanya menampilkan; fungsi tanpa return eksplisit menghasilkan None. Simpan nilai dengan hasil = fungsi(...), lalu tampilkan atau pakai kembali.

Fungsi murni menghasilkan hasil yang sama untuk argumen yang sama dan tidak mengubah keadaan luar. Kode skor_jawaban(jawaban, kunci) dapat diuji langsung dengan normalisasi tanpa menjalankan interaksi pengguna.

Python · fungsi kuis murni
def skor_jawaban(jawaban, kunci):
    cocok = jawaban.strip().lower() == kunci.strip().lower()
    return 10 if cocok else 0

assert skor_jawaban(" DEF ", "def") == 10

Refactoring aman: simpan test case; pindahkan rumus ke fungsi; jalankan uji yang sama; bandingkan keluaran. Hindari mengubah rumus sekaligus mengubah susunan kode karena bug baru sulit dibedakan dari perubahan kebijakan.

✓

if __name__ == "__main__": main() memungkinkan berkas diimpor untuk pengujian tanpa langsung meminta input dari pengguna.

Praktikum, tantangan, dan evaluasi

Refactor kalkulator dengan fungsi murni, main, kontrak, dan uji regresi.

Praktikum kasus: refactor kalkulator parkir menjadi biaya_parkir(jam) dan main(). Fungsi hanya menerima jam bulat minimal satu; antarmuka menolak jam tidak sah sebelum pemanggilan.

Enam tantangan

  1. Buat luas_persegi(sisi).
  2. Buat rata_dua(a, b) lalu gunakan hasilnya dalam klasifikasi.
  3. Buat skor_jawaban(jawaban, kunci) tanpa input atau print dan uji huruf kapital.
  4. Tambah fungsi diskon terpisah dan gunakan return-nya dalam total tagihan.
  5. Refactor kuis menjadi tanya() yang mengembalikan skor pertanyaan.
  6. Refactor tarif parkir, tulis docstring, uji 1/2/3 jam, dan tolak durasi 0.
Studi kasus mandiri: kalkulator parkir modular

Rancangan: biaya_parkir(jam) menghitung Rp3.000 untuk jam pertama dan Rp2.000 untuk setiap jam berikutnya. main() membaca input, memvalidasi minimal satu jam, memanggil fungsi, dan mencetak hasil.

JamEkspektasi
1Biaya Rp3.000; tambah satu jam Rp5.000
2Biaya Rp5.000; tambah satu jam Rp7.000
0Durasi tidak valid; tidak ada tagihan

Pengembangan menambahkan fungsi diskon terpisah. Kasus lama harus tetap menghasilkan tarif yang sama; kasus baru harus mengubah total hanya berdasarkan kontrak diskon.

Evaluasi formatif
  1. Parameter adalah nama pada definisi; argumen adalah nilai pada pemanggilan.
  2. return mengirim nilai dan mengakhiri jalur fungsi.
  3. Fungsi murni mudah diuji dan tidak bergantung pada keadaan luar.
  4. Refactoring memerlukan uji regresi agar susunan baru mempertahankan perilaku lama.
  5. Kontrak membantu menjelaskan prasyarat dan mencegah pemanggilan pada data tidak sah.
