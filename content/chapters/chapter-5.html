01

if, elif, dan else memilih jalur

Cabang saling eksklusif diperiksa berurutan.

if menjalankan tindakan saat kondisi benar. if-else memberi dua alternatif. Rangkaian if-elif-else memilih cabang pertama yang benar lalu menghentikan pemeriksaan sisanya. Gunakan beberapa if terpisah hanya bila lebih dari satu tindakan boleh terjadi.

PREDIKATA >= 80; B >= 70; C >= 60; selainnya DVALIDASI TERLEBIH DAHULUif not 0 <= nilai <= 100: tolak

Urutan ambang harus dari tertinggi ke terendah untuk predikat berbasis batas. Nilai 85 yang diuji >= 60 lebih dahulu tidak pernah masuk kategori A. Uji 79,99; 80; 69,99; dan 70 untuk membuktikan batas.

Python · klasifikasi nilai
nilai = 75
if not 0 <= nilai <= 100:
    print("Nilai tidak valid")
elif nilai >= 80:
    print("A")
elif nilai >= 70:
    print("B")
elif nilai >= 60:
    print("C")
else:
    print("D")
!

Indentasi menentukan cabang tempat else atau elif berada. Ambang yang tumpang tindih juga perlu dirancang agar hasil tidak ambigu.

02

Validasi teks dan game pilihan

Seragamkan teks lalu tentukan apakah pilihan itu sah.

strip() membuang spasi tepi dan lower() menyeragamkan huruf. Normalisasi membuat " YA " dan "ya" sama, tetapi tidak mengubah pilihan tidak dikenal menjadi pilihan sah.

Peminjaman perpustakaan membutuhkan anggota aktif, tidak ada keterlambatan, dan jumlah buku kurang dari tiga. Gunakan and untuk kelayakan. Jika penolakan boleh mempunyai beberapa alasan, tulis if terpisah untuk setiap alasan.

Python · normalisasi pilihan
aktif = input("Anggota aktif (ya/tidak): ").strip().lower()
terlambat = input("Ada keterlambatan (ya/tidak): ").strip().lower()
if aktif not in ("ya", "tidak") or terlambat not in ("ya", "tidak"):
    print("Jawaban harus ya atau tidak.")
else:
    boleh = aktif == "ya" and terlambat == "tidak"
    print("Diizinkan" if boleh else "Ditolak")

Percabangan bersarang membuat keputusan tahap kedua bergantung pada tahap pertama. Di perpustakaan pilihan baca/diskusi tersedia; di laboratorium pilihan kode/uji tersedia. Pilihan satu jalur tidak boleh dibaca sebagai pilihan jalur lain.

Praktikum, tantangan, dan evaluasi

Uji normal, batas, penolakan, regresi, dan semua akhir game.

Praktik kasus peminjaman perpustakaan: anggota aktif, tidak terlambat, dan jumlah buku kurang dari tiga. Jawaban teks dinormalisasi dan harus sah. Kasus pengembangan menambahkan status buku tersedia.

Enam tantangan

  1. Pesan lulus untuk skor minimal 10.
  2. Predikat A ≥ 80, B ≥ 70, C ≥ 60, D di bawah 60.
  3. Susun game dua tahap dengan empat akhir dan satu jalur tidak valid.
  4. Tambahkan status buku tersedia sambil menjaga semua uji lama.
  5. Ubah satu aturan peminjaman, lalu bandingkan versi lama dan baru pada input yang sama.
  6. Telusuri satu batas pada game perpustakaan/laboratorium dan tambahkan uji penolakan baru.
Studi kasus dan rancangan pengujian

Tujuan: menentukan kelayakan peminjaman dan menjelaskan alasan penolakan secara tepat.

MasukanEkspektasi
ya; tidak; 2Peminjaman diizinkan
ya; tidak; 3Batas pinjaman tercapai
tidak; ya; 3Tiga alasan penolakan dapat ditampilkan
mungkin; tidak; 0Jawaban tidak valid

Kumpulkan pseudocode atau flowchart, kode, tabel uji, dan bukti eksekusi. Tambahkan status buku tersedia pada pengembangan; kasus ini wajib mengubah hasil hanya bila aturan baru benar-benar dipenuhi atau dilanggar.

Evaluasi formatif dan refleksi
  1. elif memeriksa kondisi berikutnya hanya jika kondisi sebelumnya salah.
  2. Urutan ambang wajib menghitung kategori tertinggi lebih dahulu agar tidak tertangkap batas rendah.
  3. Validasi memeriksa bentuk/domain; keputusan menerapkan aturan layanan.
  4. Indentasi menentukan kedalaman dan kepemilikan pernyataan terhadap cabang.
  5. Jawaban tidak dikenal tidak boleh ditafsirkan sebagai jawaban “tidak”.
  6. Uji penolakan harus memeriksa bahwa skor atau data tidak berubah.
